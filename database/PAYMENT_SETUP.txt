UPDATE payment_config

5. WEBHOOK CONFIGURATION (IMPORTANT!)
=================================================================

Midtrans sends payment notifications to your webhook URL.

A. SANDBOX TESTING (localhost):

Gunakan ngrok untuk expose localhost:

1. Download ngrok: https://ngrok.com/download
2. Extract dan run:
   ngrok http 80
   
3. Copy HTTPS URL (e.g., https://abc123.ngrok.io)

4. Set webhook di Midtrans Dashboard:
   Settings → Configuration → Payment Notification URL
   
   URL: https://abc123.ngrok.io/kopi-jago/Rekayasa_E-Bisnis-Kopi_Jago/backend/api/index.php?path=payments/notification
   
   Method: POST

B. PRODUCTION:

URL: https://yourdomain.com/backend/api/index.php?path=payments/notification

Pastikan server dapat menerima POST request dari Midtrans IP:
- 103.208.23.0/24
- 103.208.23.6
- 103.127.16.0/23

7. CUSTOMER PAYMENT FLOW
=================================================================

1. Customer complete checkout (checkout.html)
   → Order created with payment_status = 'pending'

2. Customer redirected to payment.html?order_id=123

3. Customer chooses payment method:
   - QRIS → Snap popup dengan QR code
   - GoPay → Deeplink ke GoPay app
   - Bank Transfer → VA number displayed
   - ShopeePay → Deeplink ke ShopeePay

4. Customer completes payment:
   - Snap: handled by Midtrans popup
   - VA: customer transfers manually

5. Midtrans sends webhook to payments/notification

6. Backend updates:
   - payment_transactions.transaction_status
   - orders.payment_status ('paid' or 'failed')

7. Customer notified via notifications table

8. Customer can check status:
   - orders.html (payment_status badge)
   - GET /payments/check?order_id=123

8. PAYMENT STATUS MAPPING
=================================================================

Midtrans Status → Our payment_status:

capture    → paid
settlement → paid
pending    → pending
deny       → failed
cancel     → failed
expire     → failed
refund     → refunded

11. ADMIN MONITORING
=================================================================

Admin can view payment transactions:

Query:
SELECT 
    pt.transaction_id,
    o.order_number,
    pt.payment_method,
    pt.gross_amount,
    pt.transaction_status,
    o.payment_status,
    pt.created_at
FROM payment_transactions pt
JOIN orders o ON o.id = pt.order_id
ORDER BY pt.created_at DESC
LIMIT 50;

12. TROUBLESHOOTING
=================================================================

PROBLEM: Snap popup tidak muncul
SOLUTION: 
- Check browser console errors
- Verify client_key loaded (Network tab → payments/config)
- Check Midtrans script loaded (snap.js)

PROBLEM: Webhook tidak diterima
SOLUTION:
- Test webhook manually:
  curl -X POST http://localhost/.../payments/notification \
  -H "Content-Type: application/json" \
  -d '{"transaction_id":"test","order_id":"ORD-123",...}'
- Check ngrok tunnel active
- Verify URL di Midtrans dashboard benar
- Check payment_notifications table (raw_notification)

PROBLEM: Payment success tapi order masih pending
SOLUTION:
- Check payment_notifications.is_valid (signature valid?)
- Check payment_transactions.transaction_status
- Check orders.payment_status updated
- Manual update jika perlu:
  UPDATE orders SET payment_status='paid' WHERE order_number='ORD-123';

PROBLEM: Error "Payment gateway belum dikonfigurasi"
SOLUTION:
- Update payment_config dengan real credentials
- Restart Apache jika perlu
- Test: SELECT * FROM payment_config WHERE is_active=1;

14. API ENDPOINTS SUMMARY
=================================================================

PUBLIC:
GET /payments/config
→ Returns: { client_key, is_production }

CUSTOMER (Auth Required):
POST /payments/create
Body: { order_id, payment_method, bank? }
→ Returns: { snap_token, va_number?, qr_string?, ... }

GET /payments/check?order_id=123
→ Returns: { payment_status, transaction_status, ... }

WEBHOOK (Midtrans → Server):
POST /payments/notification
Body: Midtrans notification payload
→ Returns: { message: "Notification processed" }
